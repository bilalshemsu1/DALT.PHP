# Organize issues with labels

Priority gives every issue one urgency level. Labels give a workspace its own
many-dimensional vocabulary: an issue may be both “Bug” and “Backend”, while another
workspace can use completely different names.

> **Helpful background:** PostgreSQL's [constraint guide](https://www.postgresql.org/docs/18/ddl-constraints.html)
> covers foreign keys, composite keys, and referential actions used by this model.

## Model workspace labels and the many-to-many join

Create `database/migrations/011_create_workspace_labels.sql`. The label belongs to a
workspace and uses a controlled color name rather than accepting arbitrary CSS:

```sql
CREATE TABLE labels (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    workspace_id BIGINT NOT NULL,
    name VARCHAR(30) NOT NULL,
    color VARCHAR(20) NOT NULL,
    CONSTRAINT labels_workspace_foreign
        FOREIGN KEY (workspace_id) REFERENCES workspaces(id) ON DELETE CASCADE,
    CONSTRAINT labels_name_check
        CHECK (char_length(btrim(name)) BETWEEN 2 AND 30),
    CONSTRAINT labels_color_check
        CHECK (color IN ('slate', 'green', 'blue', 'amber', 'red', 'purple'))
);

CREATE UNIQUE INDEX labels_workspace_name_unique
    ON labels (workspace_id, lower(name));
```

The expression index makes `Bug` and `bug` the same name inside one workspace while
allowing another workspace to create its own Bug label.

Now connect issues and labels:

```sql
CREATE TABLE issue_labels (
    issue_id BIGINT NOT NULL,
    label_id BIGINT NOT NULL,
    CONSTRAINT issue_labels_primary PRIMARY KEY (issue_id, label_id),
    CONSTRAINT issue_labels_issue_foreign
        FOREIGN KEY (issue_id) REFERENCES issues(id) ON DELETE CASCADE,
    CONSTRAINT issue_labels_label_foreign
        FOREIGN KEY (label_id) REFERENCES labels(id) ON DELETE CASCADE
);
```

The composite primary key prevents attaching the same label twice. Cascades remove
orphaned join rows, not the issue on the other side. Run `php artisan migrate`.

## Add a protected workspace label API

Register collection, creation, and deletion routes in `routes/routes.php`:

```php
$router->get('/workspaces/{workspace}/labels', 'workspaces/show.php')
    ->only('auth');
$router->get('/api/workspaces/{workspace}/labels', 'api/labels/index.php')
    ->only(ApiAuth::class);
$router->post('/api/workspaces/{workspace}/labels', 'api/labels/store.php')
    ->only([ApiAuth::class, 'csrf']);
$router->delete('/api/workspaces/{workspace}/labels/{label}', 'api/labels/destroy.php')
    ->only([ApiAuth::class, 'csrf']);
```

The first route serves the existing workspace React shell for a refreshed or pasted
labels URL. The client router still owns the in-app `labels` screen; both halves are
needed for a durable SPA deep link.

Any member can list labels because collaborators need them in issue editing. Creation
and deletion call `WorkspaceAccess::MANAGE_MEMBERS`, our existing owner-only
workspace-management capability. Validate the name, palette value, and case-insensitive
duplicate before insertion.

Deletion scopes both IDs:

```php
$label = $database->query(
    'SELECT id, name FROM labels
     WHERE id = :id AND workspace_id = :workspace_id',
    ['id' => (int) $labelId, 'workspace_id' => $workspace['id']],
)->findOrFail();
```

That repeated workspace predicate is the difference between “label 8 exists” and
“label 8 belongs to the workspace this request already authorized.”

## Validate the complete attachment set

The edit form submits `label_ids` as JSON inside our URL-encoded request. Add
`IssueData::labelIds()` to decode it, require positive integer IDs, remove duplicates,
and count only rows belonging to the current workspace. If the count differs, return:

```php
return Response::json([
    'errors' => ['labels' => 'Choose labels from this workspace.'],
], 422);
```

Do not attach the valid subset of a partly forged request. Once the whole set is
valid, replace the issue's join rows inside one transaction:

```php
Transaction::run($database, function () use ($database, $issue, $labelIds): void {
    // Update the issue's normal fields first.
    $database->query(
        'DELETE FROM issue_labels WHERE issue_id = :issue_id',
        ['issue_id' => $issue['id']],
    );
    foreach ($labelIds as $labelId) {
        $database->query(
            'INSERT INTO issue_labels (issue_id, label_id)
             VALUES (:issue_id, :label_id)',
            ['issue_id' => $issue['id'], 'label_id' => $labelId],
        );
    }
});
```

Replacement makes attachment and detachment one simple contract. The transaction
prevents a failed insert from leaving the issue with no labels.

Extend `IssueData::present()` to query ordered public label fields and add `labels`
to every issue response. This introduces a deliberately visible repeated query; when
large lists create measurable pressure, a later performance lesson can replace it
without hiding why eager loading matters.

## Manage and attach labels in React

Create `resources/app/labels-data.ts` with runtime-checked `fetchLabels`,
`createLabel`, and `deleteLabel` functions. Create `LabelsPage.tsx`, register the
`labels` client route beside `members`, and link it from the workspace. Owners see the
creation and deletion controls; members see the shared vocabulary.

In `EditIssuePage.tsx`, fetch the issue, members, and workspace labels together.
Initialize selected IDs from the issue and use native checked controls:

```tsx
{labels.map((label) => (
  <label key={label.id}>
    <input
      type="checkbox"
      checked={labelIds.includes(label.id)}
      onChange={() => toggleLabel(label.id)}
    />
    {label.name}
  </label>
))}
```

React owns the current selection, but PHP validates every submitted ID. Display label
names on issue rows and the detail page; color remains supplementary, never the only
meaning.

## Prove workspace isolation

The backend test creates two labels, rejects a case-only duplicate, creates a label
in another workspace, and proves a mixed valid/foreign set changes nothing. It then
attaches two valid labels and deletes one, proving the join cascade leaves the other.
The React test selects two checkboxes and inspects the submitted JSON set.

Run:

```bash
php artisan test tests/Feature/IssueApiTest.php tests/Feature/WorkspaceAuthorizationTest.php
npm run typecheck
npm run lint
npm test -- --run resources/app/issue-workflow.test.tsx
```

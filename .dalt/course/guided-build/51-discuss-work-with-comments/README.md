# Discuss work with comments

Issues now describe and organize work, but decisions still happen elsewhere. We will
add a chronological conversation whose author comes from the authenticated session,
never from a browser-supplied user ID.

## Store authored comments

Create `database/migrations/012_create_issue_comments.sql`:

```sql
CREATE TABLE comments (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    issue_id BIGINT NOT NULL,
    author_id BIGINT NOT NULL,
    body TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT comments_issue_foreign
        FOREIGN KEY (issue_id) REFERENCES issues(id) ON DELETE CASCADE,
    CONSTRAINT comments_author_foreign
        FOREIGN KEY (author_id) REFERENCES users(id) ON DELETE CASCADE,
    CONSTRAINT comments_body_check
        CHECK (char_length(btrim(body)) BETWEEN 1 AND 2000)
);

CREATE INDEX comments_issue_chronology_index
    ON comments (issue_id, created_at, id);
```

The final `id` gives equal timestamps a stable order. A deleted issue removes its
conversation; deleting an account removes comments authored by it in this project’s
current retention policy. Run `php artisan migrate`.

## Centralize the nested lookup

Comment listing, creation, and deletion all need the same workspace → project → issue
boundary. Create `app/Http/IssueScope.php`:

```php
$workspace = WorkspaceAccess::findOrFail($database, $workspaceId);
$project = $database->query(
    'SELECT id FROM projects
     WHERE id = :id AND workspace_id = :workspace_id',
    ['id' => $projectId, 'workspace_id' => $workspace['id']],
)->findOrFail();
$issue = $database->query(
    'SELECT id, title FROM issues
     WHERE id = :id AND project_id = :project_id',
    ['id' => $issueId, 'project_id' => $project['id']],
)->findOrFail();
```

Return all three rows. This helper does not weaken authorization: it starts with our
membership policy and binds every child to its parent.

## List and create conversation entries

Register authenticated list, protected create, and protected delete routes below the
issue API routes. In `api/comments/index.php`, call `IssueScope::findOrFail()` before
querying comments and join users only for the public author name:

```sql
SELECT comments.id,
       comments.author_id,
       users.name AS author_name,
       comments.body,
       comments.created_at
FROM comments
JOIN users ON users.id = comments.author_id
WHERE comments.issue_id = :issue_id
ORDER BY comments.created_at, comments.id
```

Return `author: { id, name }` and camel-cased `createdAt` for React.

In `api/comments/store.php`, trim and validate one to 2,000 characters, then obtain
the author from DALT’s authenticated server session:

```php
$userId = (new Authenticator())->id();
if ($userId === null) abort(401);

$database->query(
    'INSERT INTO comments (issue_id, author_id, body)
     VALUES (:issue_id, :author_id, :body)',
    [
        'issue_id' => $scope['issue']['id'],
        'author_id' => $userId,
        'body' => $body,
    ],
);
```

Read the stored timestamp and current user name back for the 201 response. React can
render that confirmed snapshot immediately without pretending an optimistic object
was persisted.

## Give deletion an explicit policy

First scope the comment to the already-authorized issue. Then allow its author or a
workspace owner:

```php
if (
    (int) $comment['author_id'] !== $userId
    && $scope['workspace']['role'] !== 'owner'
) {
    abort(403);
}
```

An outsider still gets the earlier 404 membership boundary. A known member who tries
to delete another author’s comment receives 403. The interface may hide the button,
but this server condition is the permission.

## Carry role into the project shell

Comment moderation needs the current workspace role on the issue screen. Add `role`
to `resources/views/projects/show.view.php` and to `ProjectPageData`. This repeats the
page-boundary lesson we learned for workspace screens: a value available in PHP does
not reach React unless the JSON shell deliberately includes and parses it.

## Build the conversation panel

Create `resources/app/comments-data.ts` with runtime-checked list, create, and delete
functions. In `CommentsPanel.tsx`, load the collection when the issue ID changes.
Render a useful empty state, author, timestamp, preserved line breaks, and body.

The form disables submission while the request is pending:

```tsx
const comment = await createComment(base, data.form.csrfToken, body)
setComments((current) => [...current, comment])
setBody('')
```

Do not clear the textarea before the request succeeds. On failure, keep the learner’s
words and show an error. Use `useSession()` only to decide whether the current author
gets a delete button; owners also see it through `data.workspace.role`.

Mount `<CommentsPanel>` on the issue detail page after the issue has loaded. The API
base includes all three nested IDs, so refreshing a deep URL reaches the same
authorized conversation.
